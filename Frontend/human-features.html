Human Language — Feature Reference

This document summarizes the capabilities that are currently available in Human v0.1.8. The goal is to help readers understand what the language can do today and how it can be used in practice.

What Human supports today

Human now combines a readable syntax with a runtime that can support:

  • simple scripts and command-line tools
  • data processing and algorithms
  • typed functions and generics
  • rich standard-library helpers
  • web routes, middleware, authentication, sessions, uploads, downloads, and docs
  • runtime-native frontend interfaces with DOM nodes, events, styling, layout primitives, reactivity, storage/history helpers, and hot-reload support
  • SQLite-backed data access, ORM-style helpers, transactions, and relations
  • Python interop for trusted integrations

1. Core language features

Variables and expressions

set name to "Ada"
set score to 100
set active to true
print name

Conditionals and loops

set age to 25
if age is greater than 18 then
    print "Adult"
else
    print "Minor"
end if

loop from 1 to 3 do
    print "Hello"
end loop

Functions

define greet with name
    return "Hello, " + name
end define

print greet("Ada")

2. Typed annotations and generics

Human supports optional type hints for readability and future tooling.

function add with a: int, b: int -> int
    return a + b
end function

function<T> first_item with items: List<T> -> T
    return items[0]
end function

3. Standard library

Human ships with a growing standard library for common tasks.

Strings

set text to "hello world"
print call string_upper with text
print call string_replace with text, "world", "Human"

Lists and dicts

set nums to [1, 2, 2, 3]
print call list_unique with nums

set user to {name: "Ada", age: 37}
print call dict_get with user, "name"

Math and JSON

print call math_sum with [1, 2, 3, 4]
print call json_stringify with {ok: true}

4. Pattern matching and destructuring

set [a, b, c] to [1, 2, 3]
print a

set {name, age} to {name: "Ada", age: 37}
print name

5. Web framework and frontend runtime capabilities

Human includes a built-in web runtime that can power APIs and browser-like applications from the same runtime.

Routing and handlers

from human_language.vm import VM, Bytecode

vm = VM(Bytecode())
vm.web_controllers["home_handler"] = lambda request: vm.text_response("Hello")
vm.route("GET", "/", "home_handler")

Middleware, sessions, redirects, and responses

vm.add_request_hook(lambda request: request.setdefault("logged", True))
vm.add_response_hook(lambda request, response: response)

Response helpers

vm.ok({"ok": True})
vm.created({"id": 1})
vm.not_found({"detail": "missing"})
vm.html_response("
Hello
")
vm.redirect("/login")

OpenAPI support

Routes can be documented and exported to an OpenAPI spec using the runtime helpers.

Human’s browser-competitive frontend runtime

Human now includes a runtime-first frontend layer that competes with simple browser application stacks. This layer is designed to let you build interactive user interfaces without splitting code across separate HTML, CSS, and JavaScript tooling.

from human_language.vm import VM, Bytecode

vm = VM(Bytecode())
app = vm.dom_create_element("div", {"id": "app"})
label = vm.dom_create_element("h1", {"id": "title"})
button = vm.dom_create_element("button", {"id": "action"})

vm.dom_set_text(label, "Counter")
vm.dom_set_text(button, "Click me")
vm.dom_set_style(button, {"padding": "10px", "background": "#1d4ed8", "color": "white"})
vm.dom_append_child(app, label)
vm.dom_append_child(app, button)

count = {"value": 0}

def update_label(state):
    vm.dom_set_text(label, f"Clicked {state['value']} times")

vm.dom_add_event_listener(button, "click", lambda event: [count.__setitem__("value", count["value"] + 1), update_label(count)])

update_label(count)

Browser-competitive frontend features

  • DOM creation, insertion, traversal, cloning, and patching
  • event listeners with capture, target, and bubble phases
  • CSS-like declarations, selector matching, pseudo-state support, and media-query awareness
  • layout computation for display, sizing, padding, margin, and positioning
  • reactive stores and render helpers for state-driven UI updates
  • browser storage and history helpers for session-aware experiences
  • dev-server watch and hot-reload reporting for iterative development

6. Data layer and persistence

call db_connect with "app.db", "default"
call orm_register_model with "users", {"id": "INTEGER PRIMARY KEY", "name": "TEXT"}
call orm_create with "users", {"name": "Ada"}

Transactions and relations

with db_transaction with "default" {
    call orm_create with "users", {"name": "Grace"}
}

7. Authentication and security helpers

set cookie = call build_secure_cookie with "session_id", "abc123"
set token = call create_jwt with {user_id: 1}, "secret", 3600

8. Python interop

set np to py_import("numpy")
set arr to py_call(np, "array", [[1, 2, 3]])

9. Async and background work

The runtime supports background tasks and lifecycle hooks for long-running or request-scoped work.

10. Packaging and distribution

Human can be run from the CLI, installed from PyPI, and used as the foundation for standalone examples and app prototypes.

Recommended learning path

  1. Learn the core syntax and standard library.
  2. Build small scripts and command-line programs.
  3. Move to web routes and response helpers.
  4. Add persistence, auth, and OpenAPI docs.
  5. Connect trusted Python libraries when needed.

Production framework features

  • SQLite integration with connection pooling
  • Model registration and full CRUD operations
  • Relation management (one-to-many, many-to-many)
  • Transactions with rollback support
  • Migrations with version tracking and rollback
  • User registration and authentication with password hashing
  • JWT token creation and verification with rotation
  • Session management with TTL and CSRF protection
  • Role-based access control (RBAC)
  • Signed values using HMAC-SHA256
  • Secure cookies with HttpOnly, Secure, and SameSite
  • OpenAPI 3.0 generation with schema integration

Extensibility

Human can be extended by adding builtins in the VM layer, packaging reusable modules, and publishing them for other projects.
